# Machine config

File: `<base dir>/factory/config.yml`, by default `~/.config/t3fac/factory/config.yml`. Parsed by [`apps/server/src/factory/config.ts`](https://github.com/original-solutions/t3code-factory/blob/main/apps/server/src/factory/config.ts) (`parseMachineConfig`). Example: [`factory/config.example.yml`](https://github.com/original-solutions/t3code-factory/blob/main/factory/config.example.yml).

## Schema

| Key                         | Type         | Required | Default | Rule                                                                                                                                                                                                                                                                      |
| --------------------------- | ------------ | -------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `gh_config_dir`             | string       | yes      |         | Non-empty. Full path; `~` is not expanded.                                                                                                                                                                                                                                |
| `poll_seconds`              | integer ≥ 10 | no       | `60`    |                                                                                                                                                                                                                                                                           |
| `max_concurrent_runs`       | integer ≥ 1  | yes      |         | Across all repos.                                                                                                                                                                                                                                                         |
| `max_concurrent_gates`      | integer ≥ 1  | no       | `2`     |                                                                                                                                                                                                                                                                           |
| `feedback_seconds`          | integer ≥ 0  | no       | `600`   | Seconds between feedback reads of a `pr-open` run; `0` reads every pass.                                                                                                                                                                                                  |
| `notify`                    | boolean      | no       | `true`  | macOS notification per new attention item.                                                                                                                                                                                                                                |
| `min_free_gib`              | integer ≥ 0  | no       | `10`    | Free GiB floor; `0` turns the check off.                                                                                                                                                                                                                                  |
| `max_load_per_core`         | integer ≥ 0  | no       | `1`     | 1-minute load per core ceiling; `0` turns the check off.                                                                                                                                                                                                                  |
| `deploy_wait_minutes`       | integer ≥ 1  | no       | `120`   | Minutes a build autodeploy has waiting holds claims back before it installs whatever is in progress; factory runs resume, a person's thread is interrupted. Counted from the first wait or the end of the last snooze, whichever is later; an update now installs sooner. |
| `model_fallbacks`           | mapping      | no       | none    | Model id → another model id on the same provider instance, used while the first model's provider rate limit cools down.                                                                                                                                                   |
| `prune_branches_after_days` | integer ≥ 1  | no       | `14`    | Age of the last commit after which an unmerged local `t3/*` branch with no pull request at its tip is pruned.                                                                                                                                                             |
| `prune_branches_dry_run`    | boolean      | no       | `false` | The prune decides and logs `would prune` lines, and deletes nothing.                                                                                                                                                                                                      |
| `default_project`           | mapping      | no       | none    | The block a T3 project with no `factory` block is watched with. See below.                                                                                                                                                                                                |

`default_project` keys. Any other key is an error `default_project.<key>: unknown key`, or `default_project.limits.<key>: unknown key` under `limits`. A settings save keeps the block.

| Key                           | Type            | Required | Default | Rule                                  |
| ----------------------------- | --------------- | -------- | ------- | ------------------------------------- |
| `instructors`                 | list of strings | yes      |         | At least one login.                   |
| `limits.minutes`              | integer ≥ 1     | no       | `180`   | As the repo block's.                  |
| `limits.gate_retries`         | integer ≥ 0     | no       | `2`     | Optional here, unlike the repo block. |
| `limits.checks_minutes`       | integer ≥ 1     | no       | `30`    | As the repo block's.                  |
| `limits.interruption_resumes` | integer ≥ 0     | no       | `2`     | As the repo block's.                  |

The resolved config and the inference: [Repo config → The default block](/agents/repo-config#the-default-block).

| Retired key      | Load result                       |
| ---------------- | --------------------------------- |
| `model_instance` | Warning. Kept by a settings save. |
| `model`          | Warning. Kept by a settings save. |
| `repos`          | Warning. Kept by a settings save. |

Any other top-level key: error `unknown key <key>`.

Errors print as `<file>: <field>: <message>`. A missing file means the factory is idle (`no factory config`); a file with errors means the factory is idle and an attention item `config` is open.

## Reload

| Event                                                | Reads the file                                                                          |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Server start                                         | yes                                                                                     |
| `POST /api/factory/config` (Settings → Factory save) | yes, after validating; a failing body is 422 `invalid_config` and the file is unchanged |
| Hand edit                                            | no; applies at the next save or restart                                                 |

| Key                                                   | Applies after a save                                                                                                                                                                                                                                                            |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `poll_seconds`                                        | at once                                                                                                                                                                                                                                                                         |
| `max_concurrent_runs`                                 | next pass                                                                                                                                                                                                                                                                       |
| `max_concurrent_gates`                                | next pass                                                                                                                                                                                                                                                                       |
| `feedback_seconds`                                    | next pass                                                                                                                                                                                                                                                                       |
| `min_free_gib`                                        | next pass                                                                                                                                                                                                                                                                       |
| `max_load_per_core`                                   | next pass                                                                                                                                                                                                                                                                       |
| `deploy_wait_minutes`                                 | next pass, for the `deploy-waiting` item; `autodeploy.sh` reads the file itself on each tick                                                                                                                                                                                    |
| `model_fallbacks`                                     | next pass                                                                                                                                                                                                                                                                       |
| `prune_branches_after_days`, `prune_branches_dry_run` | next prune of each repo                                                                                                                                                                                                                                                         |
| `notify`                                              | next attention item                                                                                                                                                                                                                                                             |
| `gh_config_dir`                                       | next pass, for the factory's own `gh` calls. Sessions use the server's `GH_CONFIG_DIR` env (set in `factory/launchd/io.github.rawphp.t3fac.plist`): edit it there, then run `install.sh` on the built archive (`deploy.sh` refuses the uncommitted edit until it is committed). |

Settings → Factory edits `gh_config_dir`, `poll_seconds`, `max_concurrent_runs`, `max_concurrent_gates`, `feedback_seconds`, `min_free_gib`, `max_load_per_core`. It keeps `notify`, `keep_versions`, `default_project`, `deploy_wait_minutes`, `model_fallbacks`, `prune_branches_after_days`, `prune_branches_dry_run` and the retired keys, and drops unknown keys.

A pass reads the free space of the volume holding the worktrees folder T3 uses now (Settings → Storage, else `<base>/worktrees`) and of the one holding the data dir, and takes the lower. Below `min_free_gib` it claims nothing and starts no gate (a held gate records no attempt), prints one `low disk:` line, writes `claim_skipped` with reason `low-disk`, and keeps the attention item `low-disk` open until a pass finds the space back. A probe that fails is an error line and holds nothing back. Relaunches of claimed runs are not held.

The machine is overloaded when `max_load_per_core` is above 0 and `os.loadavg()[0]` is greater than `max_load_per_core * os.availableParallelism()`; at 0 the load is never read. An overloaded pass claims nothing, prints one `high load:` line and writes `claim_skipped` with reason `high-load`. It raises no attention item: the load drops without a person, and an item would notify each time it flaps. A gate does not start while this factory runs another one and the machine is overloaded. It answers like a queued gate (no checkout, no lock, no `gate_command`, no attempt counted) and a later pass tries again. With no gate running, a gate starts whatever the load, so under load `max_concurrent_gates` is a ceiling and the factory runs one gate at a time. This covers building runs and `pr-open` re-gates. Relaunches of claimed runs are not held.

A session whose run ends `failed` or `cancelled` with a provider rate limit as the last line of its last message (`API Error: …` naming a 429 or `rate_limit_error`, or `All credentials for model … are cooling down`) is not an interruption and never stuck. The pass backs that model off, keyed by provider instance and model id, in memory: 5 minutes doubling to 60 for each window the model is hit again after the last one ended, or the line's retry-after (at most a day) when that is longer. A model not hit within 30 minutes of its window starts over, and a restart forgets every backoff. While a model cools down with no free `model_fallbacks` model, a repo whose T3 project runs on it claims nothing and the pass writes `claim_skipped` with that repo and reason `cooling-down`. Each pass prints one `provider cooling down until …` line per cooling model. The session is resumed once in its own thread: at once on the fallback when one is free (the resume moves the thread to it), else when the window ends. That resume does not count against `interruption_resumes`. New claims launch on the fallback until the model's window ends; relaunches use the project's model.

While `deploy-pending` is in the data dir and was rewritten in the last 30 minutes, a pass claims nothing, prints one `draining for deploy:` line and writes `claim_skipped` with reason `deploy-pending`. Past `deploy_wait_minutes` it keeps the attention item `deploy-waiting` open until the marker is gone or the wait drops under a raised limit. A marker older than 30 minutes prints one `deploy-pending is stale:` line and holds nothing back; autodeploy removes it when it runs with no clone set, and a person deletes it after unloading the job. While a snooze in `deploy-snoozed` lasts, the pass prints one `deploy snoozed until` line, claims as normal and clears `deploy-waiting`; once it ends, claims are held again and the wait counts from its end. A build gets at most 3 snoozes of an hour each. `deploy-now` (update now) has autodeploy install the build it names on its next tick, before `deploy_wait_minutes`, over the runs in progress. Relaunches of claimed runs are not held.

Once an hour per watched repo, as the last step of a pass that could read the ledger, the factory prunes `refs/heads/t3/*` and `refs/remotes/origin/t3/*` in the checkout ([`t3/branchPrune.ts`](https://github.com/original-solutions/t3code-factory/blob/main/apps/server/src/factory/t3/branchPrune.ts)). It keeps a branch that a worktree has checked out, that a thread neither archived nor deleted is on, that an unfinished run's ledger names as its work or its base, or that an open or draft pull request is from or onto. When one of those lookups fails it keeps every branch and prints an error line. A local branch goes when its tip is in `origin/<base>`, when a pull request merged or closed at its tip, or when it has no pull request at its tip and its last commit is older than `prune_branches_after_days`. A remote branch goes only on a pull request merged or closed at its tip: it is deleted on GitHub only if GitHub still has it at that commit, and a tracking ref GitHub no longer has is removed locally. At most 20 remote branches, drawn at random, are tried per prune; the rest wait for the next. Before a deletion, a tip that `origin/<base>` lacks is kept as `refs/factory-pruned/<sha>`, so `git gc` never takes its commits, and `{timestamp, repo, ref, sha, reason, scope}` is appended to `branch-prune.jsonl`; a failed append stops the prune. Each pruned or skipped branch is a line in the pass output, and each failed deletion an error line. Worktree folders are never touched.

## Data dir

| Path under `~/.config/t3fac/factory` | Content                                                                                                                                                                                |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `config.yml`                         | This file.                                                                                                                                                                             |
| `runs/<run id>.jsonl`                | Run ledger.                                                                                                                                                                            |
| `events.jsonl`                       | Machine log.                                                                                                                                                                           |
| `branch-prune.jsonl`                 | One line per deleted `t3/*` branch, written before the deletion. Restore a `local` line with `git branch <name> <sha>`, a `remote` one with `git push origin <sha>:refs/heads/<name>`. |
| `attention.json`                     | Open and dismissed attention items.                                                                                                                                                    |
| `claims-paused`                      | Exists while claims are paused.                                                                                                                                                        |
| `deploy-pending`                     | `<epoch seconds> <sha>`: exists while autodeploy has a build waiting; rewritten each tick it reads the status.                                                                         |
| `deploy-snoozed`                     | `<epoch seconds> <count>`: the end of the waiting build's snooze and its snoozes so far; deleted with `deploy-pending`.                                                                |
| `deploy-now`                         | `<sha>`: install that build on the next tick without waiting for the runs in progress; dropped when main has moved past it.                                                            |
| `stop-requests/<run id>`             | Pending stop request.                                                                                                                                                                  |
| `watched-projects.json`              | T3 projects each repo was watched from.                                                                                                                                                |
| `gates/<run id>.lock`                | Exists while that run's gate runs.                                                                                                                                                     |
