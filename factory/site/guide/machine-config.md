# The machine config

The machine config says how the factory runs on this Mac: which GitHub login it uses, how often it checks GitHub, and how much it does at once. It lives in `~/.config/t3fac/factory/config.yml`. Repos are not listed here: [Add a repo](/guide/add-a-repo) covers how a repo is watched, and the model comes from the T3 project.

Without the file, the server starts and the factory stays idle. Start from [`factory/config.example.yml`](https://github.com/original-solutions/t3code-factory/blob/main/factory/config.example.yml) in the repo, or save the form at Settings → Factory with the factory's server selected, which creates it.

```yaml
gh_config_dir: /Users/you/.config/t3fac/gh
poll_seconds: 60
max_concurrent_runs: 1
max_concurrent_gates: 1
notify: true
```

## Keys

| Key                         | Required | Default | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --------------------------- | -------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `gh_config_dir`             | yes      |         | The GitHub CLI config directory the factory acts through. Write the full path: nothing in this file expands `~`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `poll_seconds`              | no       | `60`    | Seconds between passes over GitHub, at least 10. A session ending or a gate finishing starts a pass at once, so this is only the longest wait for news from GitHub.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `max_concurrent_runs`       | yes      |         | Runs that may hold an issue at once, across every repo, at least 1. A run holds a slot from its claim until its session reports a pull request or the run ends. The gate and the wait for required checks take no run slot.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `max_concurrent_gates`      | no       | `2`     | Gates that may run at once, at least 1.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `feedback_seconds`          | no       | `600`   | Seconds between reads of the comments and reviews on a ready pull request, at least 0. `0` reads on every pass. Each read costs about 3 GraphQL points per waiting pull request, so at 40 waiting pull requests and a 60 second poll, `0` spends about 7,200 of the login's 5,000 points an hour; `600` spends about 720.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `notify`                    | no       | `true`  | Posts a macOS notification when something needs a person. `false` keeps the list on the Factory page and turns the notification off.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `min_free_gib`              | no       | `10`    | Free GiB the disk holding the worktrees and the factory's data must keep. Below it the factory claims no issue and starts no gate until there is room again, and a gate that waits uses up none of its attempts. `0` turns the check off.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `max_load_per_core`         | no       | `1`     | The 1-minute load average per core the machine may carry, at least 0. Above it the factory claims no issue and runs one gate at a time, and a gate that waits uses up none of its attempts. A gate still starts when none is running. `0` turns the check off.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `keep_versions`             | no       | `3`     | Installed versions autodeploy keeps besides the current one, at least 0. The job reads it at each deploy, so an edit needs no restart. See [Follow main](/guide/install#follow-main).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `model_fallbacks`           | no       | none    | The model a session moves to while its own model is rate limited, as `model id: fallback id` pairs on the same provider, for example `claude-fable-5-1: claude-opus-5-5`. A session that hits the limit carries on on the fallback in its own thread, and new issues start on it until the limit has cooled down. Without one, the factory claims nothing on that model and resumes the session once the limit has cooled down.                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `deploy_wait_minutes`       | no       | `120`   | Minutes a build that autodeploy has waiting may hold claims back, at least 1. While it waits, the factory claims no new issue so the runs in progress can finish; past this the job installs anyway: factory runs resume on the new version, and a thread of yours with an agent at work is interrupted. The job reads it at each tick; the Factory page item follows the next save or restart. See [Follow main](/guide/install#follow-main).                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `prune_branches_after_days` | no       | `14`    | Days after its last commit that a `t3/*` branch with unmerged work and no pull request is deleted, at least 1. Once an hour the factory deletes each watched repo's `t3/*` branches that are merged or abandoned. A branch stays while a worktree has it checked out, a thread that is not archived works on it, a factory run still names it, or an open or draft pull request is from it or onto it. A branch on GitHub goes only once its pull request is merged or closed. Each deletion is logged first in `branch-prune.jsonl` in the factory's data folder, with the commit. `git branch <name> <sha>` brings back a line marked `local`, and `git push origin <sha>:refs/heads/<name>` one marked `remote`. Unmerged commits stay in the checkout under `refs/factory-pruned/`, so the commit is always there; delete those refs with `git update-ref -d` once you no longer need them. |
| `prune_branches_dry_run`    | no       | `false` | `true` deletes nothing and writes a `would prune` line to the server log for each branch the factory would delete.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

Any other key is an error, and the factory stays idle until it is fixed. A version from before `keep_versions`, `deploy_wait_minutes`, `model_fallbacks`, `default_project` or the `prune_branches_*` keys rejects that key as unknown, so delete it before you roll back that far. Three keys from older versions, `model_instance`, `model` and `repos`, load with a warning instead: the current version ignores them, and a save from Settings → Factory keeps them, so a rollback to a version that needs them still starts. Delete them once you won't roll back that far.

## A default for every repo

`default_project` makes every T3 project with a GitHub `origin` a watched repo, even one with no `factory` block in its `.dw/config.yml`:

```yaml
default_project:
  instructors: [alice, bob]
  limits: { gate_retries: 2 }
```

`instructors` is required, with at least one login. `limits` takes the same keys as a repo's ([Add a repo](/guide/add-a-repo#_1-commit-the-factory-block)), and `gate_retries` defaults to `2` here. Any other key in the block is an error. A repo on the default uses its default branch as `base`, `pr` autonomy and no required checks, and the factory infers its `provision` and `gate` from the manifests on that branch each pass, so a script you add there shows up on the next pass once the checkout has fetched it. Each watched repo costs a few GitHub API calls per pass, so a machine with many GitHub projects spends more of the login's hourly limit. A repo with a `factory` block, in its checkout or on its default branch on GitHub, uses that block and nothing from here.

Without `default_project`, only repos with a `factory` block are watched.

## Changing it

Settings → Factory edits `gh_config_dir`, `poll_seconds`, `max_concurrent_runs`, `max_concurrent_gates`, `min_free_gib` (Disk floor), `max_load_per_core` (Load limit) and `feedback_seconds`. Each limit shows what the machine is doing now, such as the free space under the floor you type, and says when a value would hold claims before you save it. Edit `default_project`, `notify`, `keep_versions`, `deploy_wait_minutes`, `model_fallbacks` and the `prune_branches_*` keys in the file by hand. A save checks the whole file with the same rules the server uses at start and refuses one that would fail, so a bad value never reaches disk from the page.

The server reads the file when it starts and each time Settings → Factory saves it. It doesn't watch the file, so a hand edit takes effect at the next save from the page or the next restart.

What a save changes without a restart:

| Change                                                | Takes effect                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `poll_seconds`                                        | At once: a save starts a pass, and the next wait uses the new value.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `max_concurrent_runs`, `max_concurrent_gates`         | From the next pass. A pass already running finishes with the old values.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `feedback_seconds`                                    | From the next pass.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `min_free_gib`                                        | From the next pass.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `max_load_per_core`                                   | From the next pass.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `deploy_wait_minutes`                                 | From the next pass, for the item on the Factory page. The autodeploy job reads the file on its own at each tick.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `prune_branches_after_days`, `prune_branches_dry_run` | From the next prune, at most an hour later.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `notify`                                              | For the next item that needs attention.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `gh_config_dir`                                       | For the factory's own GitHub calls, from the next pass. Agent sessions take their login from the server's `GH_CONFIG_DIR` instead, which the LaunchAgent sets. Change both together: edit `GH_CONFIG_DIR` in `factory/launchd/io.github.rawphp.t3fac.plist` in your clone, then run `factory/scripts/install.sh release/t3fac-<version>-darwin-arm64.tar.gz` on the archive already built, which writes the plist from the edited file and restarts the server. `deploy.sh` refuses the uncommitted edit, so commit it first if you deploy instead. A session that runs as another login stops the run with `factory:stuck`. |

A file that fails to load, at start or after a hand edit and restart, leaves the factory idle with the errors in the log and on the Factory page as an item that needs attention.
